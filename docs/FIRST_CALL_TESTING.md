# 首次来电识别：安装与验收

D3 测试前请在设置点击「开启来电识别」，确认通知栏有常驻通知；开关默认关闭。下面的 60 秒测试仅用于诊断。

## 功能和安装

目标：Huawei nova 2 Plus BAC-AL00，Android 8.0 / EMUI 8。APK：
`app/build/outputs/apk/debug/app-debug.apk`。安装更新应保留原应用数据。

首次安装后打开一次 App，进入「设置」：

1. 点击「允许电话和通话记录权限」，允许两个运行时权限。
2. 点击「允许显示在其他应用上层」，打开此应用的悬浮窗开关，返回确认三项均显示「已允许」。
3. 若永久拒绝过权限，使用「授权失败？打开应用权限设置」恢复。
4. 原有录音功能仍需存储权限；拒绝存储权限不会阻止进入来电权限设置。
5. 在 EMUI 的手机管家／电池／应用启动管理中，找到餐厅通话录音，关闭自动管理后允许自动启动、关联启动和后台运行。在系统「忽略电池优化／电池优化」中允许本应用不受限制。不同固件的名称、位置可能不同；搜索这些设置名称。切勿把省电白名单操作当成代码已保证后台唤醒的证据。
6. 用另外一部手机完成下面清单。首次安装和手动「强行停止」后，Android 要求至少主动打开 App 一次。普通重启后，先解锁手机，再测试不打开 App 的来电；不承诺解锁前的 Direct Boot。

Android 8 的 manifest PHONE_STATE 广播属于后台广播例外。每次有可用号码时，短时前台服务执行查询和管理悬浮窗，系统会显示一条无号码的低优先级工作通知，完成后消失；没有全天常驻服务，也不需要每次来电前打开 App。

## 判断规则与边界

- 唯一历史来源是本机 `CallLog.Calls`，只读，不插入、不修改、不删除通话记录；不保存客户号码或建立数据库。
- 只计入 `INCOMING_TYPE`、`MISSED_TYPE`、`REJECTED_TYPE` 和 `BLOCKED_TYPE`；拨出、语音信箱等不算以前的主动来电。
- 第一条 RINGING（即使尚无号码）固定 `ringStartedAt`；仅匹配 `DATE < ringStartedAt - 5000`。重复 RINGING 不移动边界，不重复查询、不延长提示。
- Android `PhoneNumberUtils` 做规范化／E164 格式化；挪威本地八位、`+47`、`0047` 和常用分隔符等价。完整号码比较，不能凭尾号或子串匹配跨国家号码。
- 查询在线程池执行，最少列为 NUMBER/DATE/TYPE，按时间倒序，找到匹配即停止并关闭 Cursor。权限缺失、空 Cursor 返回、异常、取消都视为无法确认，不显示首次提示。
- 无号码、Private/Unknown、特殊隐藏号码占位符均忽略。日志仅 Debug 输出状态，完全不打印号码、Intent 或可能含号码的异常。
- 悬浮窗只有「第一次来电」，顶部居中，不获得焦点、不接收触摸。OFFHOOK/IDLE 立即移除；额外每 500ms 检查当前通话状态；显示最多 12 秒，服务总计最多 15 秒。Activity 退出不会留下 Activity Window 引用。
- 电话状态广播没有与 Call Log 对应的公开通话 ID 或精确起始时间。五秒余量能排除正常时序中的当前记录，但不能证明覆盖所有 OEM 延迟、异常时钟或厂商提前回填记录；上一次来电发生在这五秒内也可能被排除。请重点验收快速重拨和第一次来电。不能将此功能作为可靠客户身份凭证。
- 删除系统历史通话后，相同号码可能再次被视为首次；系统还未写入上一通电话记录时的快速重拨同样存在限制。应用不另存号码来改变这个定义。
- 华为可能限制锁屏窗口或杀死后台应用；必须实测。应用无法突破系统强停/厂商策略。设备级 PHONE_STATE 无法精确区分双卡同时来电和通话等待；这类场景优先不显示不确定提示，不影响系统接听。

## 真机验收清单

使用专门的测试号码；不要为了测试批量清除餐厅的真实通话记录。

| 场景 | 操作 | 期望 |
|---|---|---|
| 1 新号码 | 没有该号码的系统历史来电，打入 | 正常响铃，只有一个「第一次来电」 |
| 2 再次来电 | 完成第一次后，确认系统记录已落库，再次拨入 | 无首次悬浮窗 |
| 3 曾未接/拒接 | 先形成未接、拒接（或系统拦截）记录，再拨入 | 无首次悬浮窗 |
| 4 仅曾拨出 | 餐厅此前仅主动拨给 C，C 第一次打入 | 显示首次悬浮窗 |
| 5 挪威格式 | 历史 `+4791234567`，来电本地 `91234567` 或 `004791234567` | 同一号码，无首次提示 |
| 6 隐藏号码 | 隐藏 Caller ID 后拨入 | 无提示、无崩溃 |
| 7 接听 | 新号码来电，提示出现后接听 | 提示立即消失，通话正常 |
| 8 挂断/拒接 | 新号码提示出现后由任一方结束 | 提示消失，无残留 |
| 9 后台/锁屏 | 回桌面、其他 App、锁屏分别拨入 | 系统正常来电，提示可见且不挡接听/拒接 |
| 10 重启 | 完成授权与 EMUI 配置后重启、解锁，不打开 App，拨入 | 尽可能正常唤醒；记录固件与后台设置结果 |
| 11 重复事件 | 同次来电观察 Debug 日志或测试注入重复 RINGING | 仅一次 Checking previous calls 和一次 Overlay shown |
| 12 大历史 | 系统中数千条通话记录时拨入 | 电话界面无明显卡顿；匹配即停止 |
| 13 当前记录 | 在首次 RINGING 时检查当前电话提前写入记录的固件行为 | 当前记录不能被当成历史，记录广播/DATE 时差 |
| 14 超时/晚结果 | 保持响铃超过 15 秒；查询未完成前立即接听或挂断 | 提示自行消失，晚返回结果不能重新显示 |
| 15 拒绝/撤销权限 | 分别拒绝/恢复三种权限，并在提示期间撤销 | 不崩溃、不误报，设置状态正确 |
| 16 快速连续来电 | A 挂断立即 B 打入；同号立即重拨 | B 不被上一通服务停止；记录五秒历史窗口限制 |
| 17 原功能 | 搜索、刷新、展开日期、播放、确认删除和保留期清理 | 原行为保持；录音路径和文件安全边界不变 |

## 无 USB 的真机排障（Debug 诊断版 D1）

1. 覆盖安装新 Debug APK，打开设置，确认出现「测试悬浮窗」「查看来电诊断」。旧 APK 没有这两个按钮。
2. 点击「测试悬浮窗」，确认是否能看到「悬浮窗测试」。离开设置页或等待 12 秒后消失。此步骤只验证普通界面，不代表华为来电界面也允许显示。
3. 点击「查看来电诊断 → 清空诊断记录」，再进行一次来电测试；挂断后回到此处查看并截图。需要判定首次来电时，每轮先在系统电话应用删除该测试号码的全部通话记录。
4. 诊断只保留最近 32 条处理步骤与时间，不记录号码，不联网。清空只影响诊断文件，不影响录音或系统通话记录。异步写入遇到突然杀进程时可能丢失最后几个事件。
5. 只有清空标记、没有「收到响铃广播」：本轮没有记录到响铃入口，继续调查系统投递/实际安装版本/进程启动；不能直接断言是哪一种原因。
6. 「广播没有提供号码」之后没有服务启动：调查系统是否提供号码；系统拨号器能显示号码不等于第三方广播也包含号码。
7. 「系统报告空闲」：记录发生顺序，调查 OEM/双卡状态接口；不直接移除安全状态检查。
8. 「找到该号码的历史来电」「无法完成通话记录查询」「悬浮窗添加失败」分别定位到历史判定、查询、窗口添加阶段。
9. 「系统已接受来电悬浮窗」但肉眼仍不可见：窗口添加成功不能证明可见，需要继续调查 EMUI 来电界面的遮挡或显示限制。

诊断文件：`calls/CallDiagnostics.kt`。相关覆盖：`CallDiagnosticsTest`（权限门禁前的广播证据、无号码持久化、32 条上限与清空）、`FirstCallSettingsTest`（测试窗口真实创建、离开页面移除、报告与清空）。单独创建新的 Context 只证明共享偏好读取，不等价于杀进程验证。
## D2：对照来电接收路径

适用于 D1 新打开的报告仍没有 RINGING 的情况；普通悬浮窗已经显示成功。

1. 覆盖安装 `OrderEcho-first-call-diagnostics-D2.apk`，设置中点击「开始 60 秒监听测试」。此按钮启动新一轮时会自动清空诊断，运行中重复点击不会重新注册或延长测试。
2. 自动弹出的报告应出现「监听测试已启动」「运行时广播监听已注册」「已请求注册一路电话状态回调」。最后一项只代表注册请求；是否出现「电话状态回调：空闲」可提供额外回调证据，注册时可能立即收到空闲回调。
3. 在 60 秒内打入一次电话，保持响铃约 10 秒后挂断，再回到「查看来电诊断」。本次只测试事件接收，不必删除系统通话记录，也不以是否弹出首次提示作为通过标准。
4. 页面会自动刷新。拍下包含响铃事件及结束状态的报告；内容较长时向下滚动拍第二张。测试约 60 秒后自动停止；通知栏也有「停止测试」。系统睡眠或调度可能推迟超时回调。
5. 对比「收到响铃广播」（原入口）、「运行时广播：收到响铃」、「默认／SIM 1／SIM 2 电话状态回调：收到响铃」。若只有新路径工作，可据此进一步选择修复；若原入口也恢复，需要单独研究前台服务存活的影响。
6. 「此事件带有号码」不包含号码内容，不能证明号码格式有效。系统访问规则显示允许也不证明广播必达。注册失败、回调缺失或只有空闲事件需继续调查，不能直接断言是 EMUI 拦截。

探针仅包含在 Debug source set 和 Debug manifest；Release APK 不包含此服务。任何真机诊断都不要使用仪器测试来模拟或控制餐厅来电。
## D3：正式运行时来电识别

安装 `OrderEcho-first-call-D3.apk` 后，打开设置并点击「开启来电识别」，确认通知栏有同名常驻通知。无需点击 60 秒测试按钮。首次安装和 D1/D2 升级的开关默认关闭。

- 删除测试号码的系统历史来电，再从后台/桌面/锁屏打入；响铃期间观察「第一次来电」。未提示时发诊断页，查「正式运行时监听：收到响铃」后的查询与窗口结果。
- 同一号码第二次打入（保留首次未接/接听记录）不提示；拨出记录仍不计入历史来电。
- 设置或通知栏关闭：常驻通知消失、当前提示移除、后续来电不识别。停留在设置页从通知栏关闭时，开关文案也应立即更新。
- 开启后离开 App 超过 60 秒仍应监听；普通重启解锁/覆盖安装后尝试恢复；关闭后重启仍关闭。强行停止 App 后需要再次打开。
- 原清单接收入口失效的回归测试只在隔离模拟器中执行：禁用 IncomingCallReceiver 组件、开启正式监听并使用模拟 GSM 来电，验证查询和覆盖窗；测试后恢复组件。不要在餐厅手机上运行模拟呼叫或修改组件的命令。
- 真机仍须确认华为拨号界面可见性、锁屏和系统回收行为；常驻服务不是绕过系统限制的保证。
## D5：锁屏首次来电顶部提示

1. 覆盖安装 `OrderEcho-first-call-D5.apk`，设置中保持「开启来电识别」，并确认系统没有关闭本应用通知；常驻「来电识别已开启」通知仍是监听已开启的标志。
2. 删除一个测试号码的全部系统通话记录，按电源键锁屏后用该号码打入，保持响铃约 10 秒。锁屏来电界面顶部应出现仅含「第一次来电」的小提示，不显示号码，不增加铃声或震动。
3. 在提示仍显示时，直接使用华为原生接听和挂断按钮；它们必须仍可用，且接听、挂断或等待最多 12 秒后提示自动关闭。提示只占屏幕顶部，可能接收该小区域内的触摸。
4. 保留该号码的来电记录后再次打入，不应出现首次提示。解锁时仍验证原来的顶部悬浮窗。
5. 诊断页出现「锁屏：已发出系统首次来电提示」表示全屏通知路径已请求；若仍不可见，请发送锁屏来电照片和诊断页照片。
## D6：锁屏页面启动诊断

1. 覆盖安装 `OrderEcho-first-call-D6.apk`，进入「查看来电诊断」并清空记录。
2. 删除测试号码的全部系统通话记录，锁屏后用该号码打入，保持响铃至少 12 秒，再打开诊断页截图。
3. 若看到「锁屏提示：通知渠道允许全屏提示」，但没有「锁屏提示页面已创建」或「锁屏提示页面已启动」，表示华为的锁屏电话界面没有派发本应用的全屏 Activity。
4. 若看到页面已创建／已启动，却仍在锁屏来电照片中不可见，表示该页面已经运行但被华为拨号界面遮住。
5. 若看到「系统已关闭本应用通知」或「通知渠道未处于高优先级」，请截图通知设置页面；这是系统通知配置阻止了该路径。
## D7：直达锁屏提示渠道设置

1. 覆盖安装 `OrderEcho-first-call-D7.apk`，打开 App 的「设置」。
2. 点击「打开锁屏提示通知设置」。系统页面标题应为「首次来电识别（锁屏提示）」，这就是锁屏全屏提示使用的渠道，不是另外两个同名旧渠道。
3. 在该页面启用可用的高优先级／优先显示／横幅和锁屏显示选项。保持通知声音和振动关闭；若华为要求打开声音才能选择高优先级，请不要开启声音，截图该设置页。
4. 返回后清空来电诊断，删除测试号码的全部系统通话记录，锁屏测试一次，并发送诊断截图。
